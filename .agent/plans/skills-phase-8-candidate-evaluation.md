## 2. Phase 8 objective

Review skill evidence, evaluate the three candidate hypotheses, test correct selection and measure response improvement beyond the best existing composition.

A candidate must demonstrate:

- A distinct, reusable communication job that existing skills or their composition do not adequately supply.
- Clear positive, negative and confusing-neighbor boundaries supported by visible evidence and the user's chosen intent.
- Reliable selection without degrading NONE, action, language, bound or composition behavior.
- Useful incremental wording under controlled comparison, without invented facts, certainty, commitments, motives or fault.
- Human-reviewed evidence bound to the exact evaluated revision.

Success may mean approving, revising, rejecting or deferring different candidates. A rejected duplicate with convincing evidence is a useful result.

### Planning assumptions and decisions

- Work sequentially through 8A–8E. Stop for each stated human gate; do not run all milestones as an unattended expansion.
- Reuse Phase 7 infrastructure. Prefer dossiers, fixtures and small extensions to current evaluation code over new services, storage or general frameworks.
- Keep production at 21 ACTIVE definitions throughout core Phase 8. Candidate experiments use an explicitly isolated evaluation catalog, never the approved production manifest.
- Treat missing routing expressiveness as a hypothesis to investigate, not a reason to weaken metadata or immediately redesign selection.
- Preserve the original 21 runtime definitions. If evidence suggests an existing guidance change, write a separate proposed revision/comparison arm; do not silently broaden Phase 8.
- Numeric gates below come from Phase 6 where specified. Additional operational rules are proposals to freeze with human review before held-out execution.

### Draft-state / assistance-mode coverage

Phase 3, handled elsewhere, determines whether the application rewrites an existing user draft or generates a reply when the draft is empty. The Skill Engine supports both; Phase 8 must not change the upstream action policy to make a skill test pass.

Prefer one reusable communication capability across eligible `REWRITE_DRAFT` and `SUGGEST_REPLY` actions, not separate `*_rewrite` and `*_generate` skills. Evaluate both **existing draft → rewrite** and **empty draft → generate** for representative existing skills and all three candidates where applicable.

Required questions:

- Does the same supported communication need select the appropriate capability in both modes?
- Does rewriting preserve the user's existing intent, factual content, reasons, deadlines, commitments and certainty?
- Does empty-draft generation avoid inventing any of those details when they are not supplied?
- Does the skill add useful communication guidance in both modes, rather than only making an existing draft sound better?
- Does an observed difference require AgentAction-specific eligibility/application guidance, or merely different examples of the same function?

Start with mode-specific examples and existing action eligibility/application context. A routing miss caused by draft-dependent evidence extraction is not evidence of a new communication function. Consider differentiated guidance only after measured need and review, without introducing a new schema field or prompt path preemptively. A duplicate capability requires evidence that the communication job itself differs and a separate scope decision; it is not a Phase 8 default. Keep `COMPLETE_DRAFT` and the three non-wording actions in regression coverage, but do not use completion cases as a substitute for either required mode.

Apply this requirement through the milestones: 8A identifies rewrite-only evidence gaps; 8B reviews each candidate's applicability to both modes; 8C tests paired selection; 8D measures uplift within each mode; 8E records mode-specific evidence and any justified limitation. Existing A1/A2 application examples are structurally rewrite examples, not proof of empty-draft generation quality. Add evaluation coverage rather than automatically changing that authoring schema or duplicating the 21 definitions.

## 6. Candidate-specific evaluation plans

### 6.1 perspective_acknowledgement

**Hypothesis:** recognizing another person's stated interpretation without endorsing it is useful beyond emotional validation, reassurance, clarification and de-escalation.

Required evidence: a visible attributed interpretation; the user's intent to recognize that reading; enough visible context to avoid invented motives. A skill must not decide that the interpretation “makes sense” as an objective conclusion when evidence only supports acknowledging that it exists.

| Check                 | Proposed falsification probe                                                                                                                                                                        |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positives             | A brief reply was read as dismissive; an unexplained change was read as deprioritization; inconsistent displayed prices prompted a stated interpretation. Vary work, personal and service settings. |
| Negatives             | Neutral logistics; feeling only; user rejects false agreement; no visible interpretation; unsupported claims about secret dislike.                                                                  |
| Neighbors             | Emotional validation names an expressed feeling; reassurance needs a support fact; clarification asks a material unknown; de-escalation reduces visible heat without inventing a viewpoint.         |
| Hard negative         | “I feel sad” must not become an inferred explanation of why. An accusation does not authorize endorsing its factual conclusion.                                                                     |
| Both-valid            | A stated interpretation plus an explicitly stated feeling, with intent to acknowledge both. Do not force both when only one function is intended.                                                   |
| Intent/fact/certainty | Keep “it seemed to you” distinct from “that is what happened”; no motive attribution, concession, promise or forced warmth.                                                                         |
| Uplift                | Better recognition of the stated viewpoint, fewer false agreements/mind-reading claims, no unnecessary repetition.                                                                                  |
| Disproof              | Existing validation wording/composition consistently supplies the same benefit; reviewers cannot distinguish labels reliably; or guidance increases unsupported agreement.                          |

Compare against the best supported existing subset, not a deliberately weak emotional-validation-only baseline. Test mixed and unsupported-primary language rules without adding cultural claims.

### 6.2 confirmation

**Hypothesis:** verifying one understood material proposition is distinguishable from asking for missing information and adds value beyond clarification, request and planning.

Require one available interpretation, a material reason to verify, and the user's chosen verification intent. Keep sender/recipient commitments distinct.

| Check                 | Proposed falsification probe                                                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Positives             | Verify an offered Friday delivery before dependent scheduling; verify a proposed quantity before booking; verify apparent collection choice before arranging it.         |
| Negatives             | Settled trivial fact; thanks/closing; user has no chosen check; upstream ASK_CLARIFICATION/NO_REPLY_NEEDED.                                                              |
| Exact hard negative   | “Send it toward the end of the week”; user does not know Thursday or Friday → clarification, not confirmation. Do not invent Friday as the understood proposition.       |
| Neighbors             | Clarification resolves alternatives/missing scope; request seeks an action rather than verification; planning states or proposes logistics rather than rechecking them.  |
| Both-valid            | Verify one known proposition while asking a separate material unknown, only if both are user-intended. This is not one ambiguous datum relabeled as both.                |
| Intent/fact/certainty | “You offered Friday, correct?” cannot become “I will deliver Friday.” Do not assert an offer is an accepted commitment or add a question to a completed acknowledgement. |
| Uplift                | Clearer proposition and bounded verification, without extra questions, new terms or friction.                                                                            |
| Disproof              | A reviewed clarification mode or existing composition is equally useful/selectable; reviewers repeatedly disagree over material verification versus missing information. |

The skill words a user's intended question inside a wording action. It never triggers or overrides the coach's upstream ASK_CLARIFICATION decision.

### 6.3 give_constructive_feedback

**Hypothesis:** communicating observed behavior, supported impact and a desired change is independently useful, not merely status/information + request + de-escalation.

Require user-supported observation, impact and intended actionable change. Repetition/frequency must be evidenced, not inferred. Test a calm case as well as a heated one.

| Check                 | Proposed falsification probe                                                                                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Positives             | Two interruptions prevented finishing; an unannounced plan change caused a wasted trip; missing labels made figures hard to review.                                            |
| Negatives             | Suspected sabotage; ordinary scheduling limit; user owns the mistake; no feedback intent; unsupported impact or corrective demand.                                             |
| Neighbors             | Request alone seeks action; de-escalation changes heat; boundary states a limit; acknowledge_mistake owns the user's fault; status_update reports a present state.             |
| Hard negatives        | “Please stop calling after 8” without an intended feedback explanation; “this estimate may omit travel” without proven error; an angry adjective without an observed incident. |
| Both-valid            | Feedback plus independently intended request, boundary or heat reduction. Specificity must survive a four-skill composition without needless duplication.                      |
| Intent/fact/certainty | No identity labels, invented motives/incidents/frequency, wrong responsibility, false authority, humiliation or new corrective promise.                                        |
| Uplift                | Better supported specificity, constructiveness, actionability and absence of personal attack.                                                                                  |
| Disproof              | Best existing status/request/de-escalation composition matches benefit; desired-change evidence is repeatedly invented; or the function only works as a multi-step playbook.   |

For all three, test at least three cross-context settings. Relationship labels are evaluation strata based on synthetic visible context, not new production relationship inputs. Source-rights review uses internal original prose; external concepts are inspiration, not copied dialogue or proof of quality.

### 8.1 Three data partitions, plus immutable historical regression

| Historical regression    | Preserve Phase 7's 21 normalized objects, 21 integration and 132 direct/synthetic plans; these familiar cases are regression evidence, not fresh holdout.                                                                                   |
| Additional global probes | Actions, NONE, unsupported/mixed/script language, ownership, negation, prompt injection, over-cap selection and guidance budget. Not a substitute for per-definition floors.                                                                |

A human or separate case author who did not tune the candidate should author and seal holdout after the candidate boundaries are frozen. No subagent or extra task is started by this plan. If independent authorship is unavailable, disclose the limitation and defer strong approval rather than call self-authored tuning data independent.

The 12-context allocation is a floor, not a coverage ceiling. Every listed candidate neighbor needs fresh held-out exclusion evidence in both directions, with language/action safety slices represented. Expand the four-neighbor allocation where necessary, especially for feedback's five neighbors; report the resulting counts instead of treating 288 as a cap. Do not substitute development contrast checks for unseen neighbor coverage.

Assign whole scenario families to a partition: translations, paraphrases, names/numbers and superficial setting changes inherit the original family's split. Use group IDs, provenance, hashes, dedup review and a frozen split manifest. Test authoring visibility is not secrecy alone: record any exposure. Once used to diagnose/tune a failure, that family becomes development data; the next final gate needs fresh independently reviewed holdout. Keep previous results and failures.

### 8.2 Annotation and scoring contract

A fixture supplies case/group/split IDs; candidate/neighbor; raw synthetic messages and ownership; draft; fixed AgentAction and explicit intent/selection where applicable; language/script/switching; facts, commitments, certainty and responsibility ledger; expected status; required E, optional acceptable A, forbidden F; rationale; reviewer state and content hash.

Pass only when E is contained in selected S, S is contained in E union A, and S intersects F nowhere, with unique valid IDs, legal language/action, at most four selections, correct status and valid bounded guidance. Sets must be disjoint and requirements satisfiable.

When different compositions are legitimate, annotate separate valid E/A alternatives, not a union of their requirements. Accept any complete alternative and record the matched alternative; use a preregistered deterministic rule for recall/precision reporting rather than cherry-picking per metric. Keep existing single-set metric behavior and add tested support/assertions in the existing evaluation area only as needed.

Strict NONE requires E = A = empty and valid NONE/empty guidance, not merely an empty required set. Focal-candidate negatives may validly select a neighbor. Empty FAILED, fixture validation errors and no evaluation cases are not successful NONE.

Human reference labels must not be generated by production scoring/eligibility helpers. Reuse the independent language oracle in `scripts/phase-4-evaluation-support.mjs`. Include positive modifier checks so universal-only output cannot appear language-perfect.

### 8.4 Failure diagnosis before repair

| Category                    | Evidence / next action                                                                                                       |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| SKILL_DEFINITION_GAP        | Supported job is missing a necessary guidance/evidence boundary; revise draft and re-review.                                 |

For every failure store case/revisions, expected and observed plan, layer, category, evidence, proposed repair and reviewer. Distinguish a provider error, bad fixture and actual routing miss. Candidate wording can improve guidance but cannot itself change a selector that ignores prose.

### 8.5 Coverage and acceptance gates

Report by candidate, neighbor, language/script and action: required recall, allowed precision, focal candidate false positives, forbidden selection, strict NONE accuracy, complete scenario pass, boundedness, repeatability and composition failures. Include counts and denominators; N/A when unsupported, never a perfect score for no observations.

Phase 6 initial per-candidate targets: allowed precision ≥0.90 and required recall ≥0.85, with zero critical forbidden selections. Require 100% tested action/language/bound/draft-exclusion invariants, deterministic repeatability, and strict NONE accuracy on the preregistered safety/zero set. Report any noncritical misses and demand review before approval.

Four positive cases is a minimum coverage floor: a 4/4 result is not strong statistical confidence. Report binomial/context-level uncertainty where appropriate, expand weak/borderline or unbalanced slices before approval, and never lower a frozen threshold after observing holdout. Do not silently exclude hard negatives to achieve a rate.

Include English, independently authored Simplified and Traditional Chinese, intentional mixed language, en/zh regional variants, unsupported primary plus supported secondary, unknown primary and switching false. Other languages remain universal-only. All six actions are covered; candidate keywords must not override the three non-wording NONE actions.

### 8.6 Paired draft-state selection coverage

Create matched scenario families for all three candidates and representative existing capabilities: `apology`, `emotional_validation`, `boundary_setting`, `decline`, `request`, `status_update`, `expectation_setting` and `clarification`, with relevant English/Chinese modifiers. Cover positive, candidate-negative, hard-neighbor and legitimate NONE cases in both modes. For a rejected/deferred candidate, record why further mode evaluation was not run; no APPROVE recommendation may omit an applicable mode without an explicit human-reviewed eligibility limitation.

Each pair holds the communication need and supported semantic evidence constant, with two valid application inputs:

- **Rewrite:** a real synthetic user draft expresses the intended message; Phase 3 supplies REWRITE_DRAFT.
- **Generate:** the draft is genuinely empty; visible user-owned context or an explicit user selection independently supplies the same intent and necessary facts; Phase 3 supplies SUGGEST_REPLY where warranted.

Do not simply delete a draft that was the only source of the user's choice or facts and still expect the same result. The evaluator's ledger is a reference, not hidden evidence supplied to the model. Cases that lose material evidence belong to a separate information-loss control: expect conservative behavior or the appropriate upstream choice/clarification/NONE outcome, not fabricated intent or a forced reply.

Record scenario-family/pair ID, draft state, actual AgentAction, evidence source and per-mode expectations. Keep both variants in the same development/holdout partition and count them as correlated executions, not two independently authored contexts. Test both direct contexts and raw evidence derivation; current `make_request` derivation depends on draft text, so specifically diagnose missing empty-draft coverage rather than copying expected tags into the input.

Require the appropriate focal capability in both eligible matched positives, with independently annotated acceptable neighbor/modifier sets. Do not demand identical wording or every selected ID when supported application context differs. Report selection recall/precision, false positives, NONE accuracy and failures separately by mode and at pair level; pooled success must not hide failure in one mode. Investigate divergence as evidence, annotation, action eligibility, extraction or guidance issues before considering a distinct capability.

## 9. Response uplift evaluation

### 9.1 Preregistered controls and conditions

For each case freeze conversation, draft, AgentAction, intent/selection, evidence ledger, provider/model identifier/version where available, generation settings, system prompt, output budget and all non-candidate selected skills. No gold IDs, reviewer rationale or expected rewritten answer goes to the generator.

These controls apply **within each assistance mode**: run the candidate-off/candidate-on comparison separately for REWRITE_DRAFT and SUGGEST_REPLY. A rewrite-versus-generate pair necessarily changes draft state and action; it tests capability reuse, not a candidate-only causal effect. Reuse the matched semantic evidence from section 8.6 and assess preservation against the draft in rewrite mode, and grounding in visible context/explicit selection in empty-draft mode.

Use Phase 6's four conditions:

| Condition | Guidance                                                                                                     |
| --------- | ------------------------------------------------------------------------------------------------------------ |
| G         | Generic, no skills.                                                                                          |
| E         | Best human-reviewed combination of existing approved skills for this case. Freeze before inspecting outputs. |
| N         | Candidate alone, within existing limits.                                                                     |
| E+N       | Same existing composition plus candidate, subject to the four-definition and 12/12-rule bounds.              |

The primary candidate-ablation comparison is **A = E versus B = E+N**, with exactly the same non-candidate skills/order/strings surviving composition. Candidate-only N versus E tests whether a new atom outperforms the best existing alternative; beating G alone is insufficient.

Reserve a candidate slot and enough rule budget in primary A/B cases: at most three existing definitions, with candidate guidance added at a declared position. Assert that no existing rule is truncated in B. Same maximum token budget does not mean identical prompt length; disclose the extra guidance and do not claim a length-independent causal effect.

If E already needs four skills or saturates guidance, do not silently remove a skill to call it a controlled ablation. Run a separately labeled **replacement/budget-stress comparison**, predeclare the displaced optional member/rules, record both plans, and exclude it from the strict marginal A/B estimate. Keep the unconstrained best E as a reference. This refines Phase 6's replacement allowance to satisfy the required identical-non-candidate control.

Compare feedback explicitly against status/information + request + de-escalation where supported. If an equally compact, reviewed existing-skill extension appears sufficient, document a non-production comparator proposal and seek approval before introducing that extra arm; never weaken E to favor a candidate.

### 9.2 Dataset, calls and operational controls

Retain Phase 6's **12 fresh positive contexts per continuing candidate**: four English, four Simplified Chinese, four Traditional Chinese, at least three relationship/context settings; one intentional code-switch case in each Chinese group. Independently authored contexts, not canonical translations, development cases or the already-exposed selection holdout.

Within each candidate's 12 independent positive contexts, allocate six primary executions to rewrite and six to empty-draft generation (two of each per language/script group). Add the other-mode counterpart for one context per language/script group, using the paired-evidence rules in section 8.6. This yields 12 independent scenario families and 15 execution variants per candidate, not 15 independent contexts. All three candidates therefore require **45 positive execution variants × four conditions = 180 outputs** per repetition, or 360 for two. Count actual requests/outputs and failures; alternatives within one response are not independent trials.

Also retain at least 12 fresh negative/neighbor adversarial scenario families per candidate. Use the same balanced primary-mode allocation and three matched counterparts where both modes apply. At that allocation, all three candidates add **180 adversarial outputs per repetition**, making the candidate-study proposal **360 outputs for one repetition, 720 for two**. A justified non-applicable pair must be identified, not quietly dropped or used to claim both-mode success. These counts revise the earlier single-mode budget; they are not permission to spend.

Include representative existing-skill controls comparing G versus E in both modes to check useful guidance and preservation/grounding, not only candidate novelty. Reuse covered scenarios where valid; otherwise list additional controls and their output counts in the approved run manifest. Freeze the final budget including those controls, expanded coverage, repeats and permitted retries before calls. No additional calls are automatically authorized by this planning amendment.

Before execution, the user selects provider/model, token/cost ceiling, repetitions, allowed retries and review-artifact location/retention. Stop at the cap. Use existing provider-neutral coaching entry points and adapter; no new provider transport. Read/reuse credentials only through the normal approved flow, never copy or print them.

Randomize condition order per context and blind output labels/skill names. Preserve assignments and settings in a private condition map. Do not silently reroll low-quality answers: record initial failures and any allowed retries separately. Missing/provider-failed arms are reported, not counted as wins or successful pairs.

Manual guidance experiments isolate usefulness; separately report automatic candidate selection plus generation after 8C. Oracle-guided improvements alone cannot satisfy “reliably selectable.”

### 9.3 Safety-first review and evidence

Critical failures override fluency: intent/action reversal, unsupported fact/certainty/commitment, wrong speaker responsibility, invented motive, manipulation, identity attack or unjustified disclosure. Any observed critical regression blocks APPROVE until revision and fresh verification; zero observed does not prove universal safety.

Rate 1–5 (1 materially poor, 3 acceptable, 5 clearly effective):

- Intent preservation and appropriateness to visible evidence.
- Clarity and communication-goal achievement.
- Relationship/register fit without inferred intimacy, hierarchy or stereotype.
- Naturalness, script and intentional code switching.
- Proportionality: over-apology, over-formality, reassurance and unnecessary escalation.
- Interaction burden: needless questions, negotiation or added commitments.
- Candidate-specific target: viewpoint without agreement/mind-reading; verification without extra questioning; feedback specificity/constructiveness/actionability without personal attack.

Record blind win/tie/loss and short observable reasons for E+N versus E, N versus E, and each versus G. Analyze at scenario-family level; paired mode variants, repetitions, rating dimensions and two reviewers are not independent samples. Report per-language and per-mode patterns and uncertainty, not just averaged ratings. Rewrite-specific failures include altered meaning or lost qualifications; empty-draft failures include invented facts, reasons, deadlines, commitments or certainty. Require evidence of useful guidance in each applicable mode; success in rewriting cannot mask failure in generation.

Two competent human reviewers per evaluated language/script judge each pair, with adjudication for material disagreement. Automated judges may flag issues or provide secondary ratings without seeing expected skill labels. Calibrate them against human decisions; test ordering bias. One-reviewer evidence or insufficient language coverage supports a disclosed DEFER/limited research result, not strong production approval.

Phase 6's uplift gate is a favorable, defensible pattern beyond E with no critical regression. Freeze the operational decision rule before calls: wins must exceed losses for the primary target, ties are disclosed, no unresolved language-specific harm, and reviewers can explain a distinct benefit. A narrow/noisy pilot remains DEFER or motivates a preapproved fresh extension; a positive mean alone is not approval.
